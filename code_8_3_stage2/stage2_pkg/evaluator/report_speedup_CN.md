- 初始化 $m_2=\hat g_1$：用已验收的全网格核算一次，断言其支撑在 $W_2$ 内后只写入 $W_2$（这样支撑检查是真检查，而不是按构造成立）；
- 末步 $k=K$ 照旧做一次更新（$m_{K+1}$ 不用），断言检查更新后的支撑是否在 $W_K$ 内，位移一栏记 `not applicable — no next sample`。

# 2. 核零值测试与窗口几何（步骤 0、1）

核零值测试（`logs/kernel_zero_test.log`）直接调用已验收的 `_kernel`：单节点网格、$dz=1$ 时返回值就是核值本身；核值为 0.0 时归一化做 $0/0$，numba（python 错误模型）抛 `ZeroDivisionError`，所以异常恰好对应核值精确为零。四个输入每个 $x_k$ 两侧各一点，每个输入每个距离 10000 次求值：

| $|z-x|$ | 结果 |
|---|---|
| $38.5\sigma$ | 全部非零，值 $4.6286\times10^{-319}$ |
| $39\sigma$、$40\sigma$、$50\sigma$ | 全部精确为 0.0 |

所以 $\rho=39\sigma$，$R=\Delta+48\sigma=68\sigma$。族位移上界 $v_{\max}=5.449\times10^{-4}=4.570\sigma$（取 $5\sigma$）；各输入实际 $\max_k|x_{k+1}-x_k|$：U 3.99σ、D 3.18σ、E 3.84σ、N 4.04σ（只作核验，不参与窗口定义）。$n=24$ 时每个窗口 3263–3264 个节点（上界 3265）；没有窗口碰到网格两端（`logs/speedup_windows.log`）。

# 3. 断言及其依据

**归纳不变量（方案 §2）。** 初始化：$m_2=\hat g_1$ 的支撑在 $|z-x_1|<\rho$ 内，$|x_2-x_1|\le5\sigma$，所以在 $W_2$ 内。归纳步：若更新前 $\mathrm{supp}(m_k)\subset W_k$，则更新后 $\mathrm{supp}(m_{k+1})\subset\{|z-x_k|<\Delta+\rho\}\subset\{|z-x_{k+1}|<\Delta+44\sigma\}\subset W_{k+1}$。

**断言**只检查更新后 $W_{k+1}$ 两侧紧邻各 $M$ 个节点是否存在非零值（末步检查 $W_K$ 两侧），检查"是否存在非零"而不是带符号的和。它不是对整个数组的独立检查：它之所以足够，是因为由不变量和缓冲区规则，更新后 $W_{k+1}$ 之外可能的非零值只能落在 $W_k\setminus W_{k+1}$ 里，而相邻窗口端点最多移动 $5n<M$ 个节点。步骤 2 的合成自检（`logs/speedup_selftest.log`，不是运行）确认断言在下一窗口被人为移开 $2M$ 个节点时会触发、在真实下一窗口时不触发，并确认 U、$n=6$ 第一步窗口版与全网格版逐位相同。断言触发时的全网格回退只用于诊断，记录后整次运行停止；本轮从未进入回退。

# 7. 实现中的选择（供审核）

1. **独立文件而非开关**：`evaluator_fast.py` 导入已验收模块；`evaluate_fast` 在一次调用内替换 `density_recursion_v1.run_ab` 并在 `finally` 中恢复，从而共用已验收的记录、组装 $J$ 与计时代码。
2. **初始化的核**用已验收的全网格 `_kernel` 算一次（一次性 $O(G)$），使"$m_2$ 支撑在 $W_2$ 内"成为真检查；之后每步的核只在窗口上算。
3. **核缓冲区**按与质量缓冲区相同的方式先清上一步窗口再写本步窗口（方案只说窗口外的核值"是零，但索引要存在"）。
4. **核零值测试的读法**：单节点调用，返回值即核值；为 0 时由 `ZeroDivisionError` 识别。
5. **计时顺序**：12 个评价轮 3 遍，而不是每个评价连测 3 次。
6. **搜索成本的汇总**：两种汇总都报（见第 5 节）。
7. **预测文件名**为 `predictions_speedup.md`，因为同目录的 `predictions.md` 属于验收运行。
